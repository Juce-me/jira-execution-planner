## Approved behavior and boundaries

- One shared Department `allocationTypes: [{value, type}]` list (optional additive field in existing payload version 2; private preference version unchanged) holds selected raw Allocation values and each value's `product|tech` classification. Its values define DELIVERY Allocation Board membership. Blank/unmapped/unreadable Initiative Allocation is No Allocation. No Epic or Objective fallback.
- `missingInfoComponents` stays the Legacy Component selection. Never infer Allocation values or classifications from Legacy Components.
- The Jira Allocation field mapping, source projects, hierarchy and quarter ranges stay in administrator-owned Project config. Remove Product/Tech value editing there; old data must not be silently lost or remain a second writable authority.
- Department mappings belong to `workspace_group_configs`, shared and editable by every authenticated workspace user through the existing revisioned Department save. Private favorite/visibility and EPM settings stay private and unchanged.
- Legacy `scope=component` shows matching Epics. DELIVERY `scope=allocation` shows matching Initiatives and their eligible Epic children. All work unions the era's configured cohort with Department-Team work. DELIVERY's Team-only union must not widen to unrelated siblings.
- No schema migration, dependency, new App effect, or live configuration/database access. Reuse existing effects, selectors, write adapters, registered classes and control markup. Any required interface inventory changes must be deliberate and reviewed; preserve physical ceilings and App's 74-effect ceiling.

## Existing-data decision

The operator chose empty lists. Keep old global data as dormant history, but never use it as a runtime Department classifier. Existing and new Departments normalize to explicit empty mappings until configured. Missing-field saves from old clients preserve any existing Department mappings inside the workspace CAS transaction; explicit `[]` clears them. Imports preserve the selected Department's existing map when the field is omitted, and exports include its effective map. Never derive Allocation from Legacy Components and never write on GET/startup.

## Validation and safe error envelopes

The Department list retains the existing mapping rules: array only (null/string/object rejected), at most 200 entries, each object has exactly required `value` and `type`, trimmed nonempty string values at most 255 characters, `type` exactly `product|tech`, first exact duplicate wins, case-sensitive values. Unknown entry keys reject. Explicit `[]` is valid and different from omission during stale saves/imports. No SQL migration or group payload-version bump is needed for this optional field; old-client omission protection is explicit transactional behavior.

New classified task/Stats read errors are sanitized `{"error":code,"message":message}`: `400 department_required` (choose a Department), `404 department_not_found` (no workspace-local saved group), `400 department_teams_required` (configure Teams for Sprint views), and `503 config_storage_unavailable` with `Configuration storage is temporarily unavailable.`. Auth remains first (`401` terminal recovery), and no Jira request runs for these failures. Readiness keeps its existing `404 story_readiness_scope_not_found`, `409 story_readiness_configuration_invalid` with `reason:"teams_missing"`, and existing unavailable/storage handling rather than inventing a parallel envelope.

Group saves keep `400 {"error":"invalid_groups_config","errors":[...]}` for invalid mapping data, `409 {"error":"group_config_conflict","message":...,"current":...}` for stale `baseRevision`, and the existing safe `503 config_storage_unavailable` shape. Missing/invalid revision keeps its existing invalid-groups response; no draft is discarded on any failure.

Stale administrator classification edits use `400 {"error":"allocation_mapping_department_owned","status":"error","message":"Configure Allocation values in Department settings."}`; unchanged legacy map echoes and omissions remain accepted on first promotion and subsequent saves, while changed values or explicit clearing reject before mutation.

Board pre-stream failures use its existing `{"error":code,"message":"The ENG Board request could not continue safely."}` shape: wrong-era `component`/`allocation` gives `400 board_scope_model_mismatch`; empty Allocation scope gives `409 board_allocations_required`; nonempty Allocation values with missing Allocation field gives `409 board_allocation_field_required`; unknown Department keeps `404 board_group_not_found`; storage keeps its existing sanitized unavailable response. Empty-map Team-only DELIVERY All work must not require Allocation JQL or that optional field. Post-start failures keep the existing bounded NDJSON error/completeness protocol. Add every new public code to its client recovery copy/fixtures and the security contract samples when required.

## State and concurrency checks

- Dirty mapping changes stay local until the shared footer Save; Discard restores the saved mapping. Saving another settings section must not write it into administrator/private payloads.
- A 409 keeps the complete draft and existing recovery UI. Merge omission preservation from the current stored group inside the CAS transaction, not a route-level pre-read.
- Duplicate/import/export preserve mappings. Importing a legacy selected-group artifact that omits allocationTypes preserves that selected Department's current effective mapping; explicit [] clears it. Malformed imports fail before normalization or draft mutation. Export always includes effective mappings, including empty maps. New groups explicitly start empty; normal duplicates copy mappings. Removing Legacy Components must not clear Allocation.
- Allocation-only Departments can be saved, selected and favored for strict Allocation Board. DELIVERY Sprint-bound Catch Up, Planning, readiness and excluded-capacity Stats retain the Teams-required setup boundary: no Teams means no Jira discovery and the existing setup guidance, never a role-wide project fallback. Legacy behavior stays unchanged. Legacy Component scope is unavailable without Legacy Components; Allocation scope is unavailable without selected Allocation values. All work can use Teams alone.
- Saved mapping changes invalidate the affected Department's task/classification snapshots and Statistics range/chunk/automatic caches even when Teams do not change. Late responses from an old mapping or Department cannot apply.
- Two Departments sharing Teams may classify the same Initiative differently without cache leakage. Use saved Department identity plus a mapping digest; do not fold it into the shared work-configuration digest or retire Sprint catalogs/EPM caches.
- Scope/model switches retire incompatible reads through existing effects. Retain reading position, drafts, focus and the corrected Planning row-mode behavior.
- Readiness and Board capture mapping content in their authority/cohort snapshots. Raw Jira Allocation lookup caches may stay shared if they contain raw values only and apply Department classification afterward.
- Keep existing 401 terminal recovery/no replay, own-key Jira writes and token-bound CSRF behavior unchanged.
