## Assessment

The confirmed problem is **data changing underneath a reader**, rather than a demonstrated periodic page reload. A current-source synthetic Catch Up probe reproduced a priority-change refresh that remounted the read Story, reset scroll from 232px to 0, and displaced it by 330.08 CSS pixels without another document request. A second probe confirmed that a delayed automatic response applies while the simulated document is hidden and unfocused. The current long-absence path does not navigate: after more than 12 continuously unfocused/hidden minutes it requests auth renewal, then invokes the active view's manual Refresh function. Removing auth renewal would neither solve that displacement nor make 8/24-hour returns reliable.

Approved direction: **event-driven, focused-only freshness with the viewed Epic first**, followed by one bounded scope refresh with stable rendering. Keep explicit Refresh. Add no periodic Jira polling, full-page freshness reload, new fetch library, server scheduler, webhook, or configuration setting. The linked `EXEC-*` plan turns this policy into an execution contract; remaining validation gates application edits rather than plan authorship.

Interpretation: “board tab is unfocused” means the browser dashboard document is hidden or has lost window focus. The design covers the ENG Board mode as well as the Epic lists. Browser focus, the Board's focused column, and the Epic currently being read are separate concepts. The user accepted this policy and requested a planning commit and implementation plan on 2026-10-09; application execution and publication remain separate steps.

## Options and tradeoffs

| Approach | Benefit | Cost / limitation |
| --- | --- | --- |
| **Viewed Epic first, then one stable scope catch-up — recommended** | Restores relevant data quickly, finds newly added/moved work in the broader scope, and preserves where the user is reading. Reuses targeted merges and existing scope owners. | Requires explicit generation, edit, completeness, and viewport guards. Two targeted lane calls can precede the broader lane calls. Strict cross-sprint Board needs a different adapter. |
| One silent scope refresh with an anchor | Less request orchestration; scope discovery remains coherent. | The viewed Epic waits behind the whole response. Keeping a spinner off alone does not prevent priority, membership, filter, or pane movement. |
| Manual-only data refresh after absence | Smallest automatic load; no unsolicited update displacement. Auth renewal remains event-driven. | An 8/24-hour-old view can remain stale indefinitely. Requires clear age/stale guidance and deliberate Refresh. Choose this if automatic updates are unwanted. |

A fixed focused-tab interval is not recommended without evidence of a freshness requirement during uninterrupted reading. It adds ongoing Jira work and repeat ordering disruptions. This event-driven choice provides no maximum remote-data age during an uninterrupted focused session; explicit Refresh remains available. If bounded age during continuous reading is required, that is an additional policy decision. Webhooks/SSE for remote Jira changes add deployment, authorization and completeness work; the existing Scenario stream describes app drafts, not all Jira changes.

## Proposed behavior

### Triggers and freshness meaning

- Keep the existing >12-minute return threshold initially; it is a compatibility heuristic, not a measured optimum. Exactly 12 minutes retains today's behavior. Do not invent separate 8-hour and 24-hour fetch loops.
- Treat auth renewal, “this data may need checking,” data acquisition, and render application as separate transitions. Auth success alone neither fetches every view nor marks data current.
- Store in-memory check information per accepted scope and source: `lastCheckedAtMs: number|null`, `checkKind: 'forced'|'cached'|'unknown'`, `coverage: 'complete'|'partial'|'unknown'`, and pending/recoverable-failure state. No persistent user/workspace setting or DB migration.
- A completed force-read advances that source's check time, including an unchanged response. Aborted, rejected, auth-locked, or failed lanes do not. Track each lane independently; protect incomplete membership and report its coverage. A check is an observation, not a guarantee that all Jira indexing has caught up.
- A return intent is satisfied by an equal-scope forced check completed after that absence began. Otherwise coalesce it into one pending generation. Cached responses and another view's freshness never satisfy it.
- Scope changes and explicit Refresh retain their existing acquisition semantics. Filter, Team selection, sorting and grouping changes operate on the accepted scoped data; they do not trigger Jira requests just to recompute presentation.
- Keep the existing Refresh control. Show compact `Checked … ago` / `Updates pending` / `Could not check; showing previous data` state next to it using existing shell typography, without a new toolbar or toast per Story. Qualify partial/unknown coverage in the existing readout; never claim “all data up to date.” Relative age rendering must not schedule network work.

### Focus and one pending generation

Automatic acquisition/application is eligible only when `document.visibilityState === 'visible' && document.hasFocus()`, the requested surface is active, its scope is accepted, bootstrap is complete, and auth/connection recovery does not own the page. An open editor/popover, in-flight mutation/drag/save, or dirty Planning/Scenario/Settings draft defers automatic application. Conservatively defer the whole refresh while a dirty draft is present rather than trying to reconcile its base revisions implicitly.

On blur/hidden, retire automatic read controllers and staged results, record one pending intent, and stop all freshness follow-up reads. A late result cannot commit. If a transport cannot be stopped immediately, its generation guard must discard it; cancellation cannot undo upstream work already sent. Already-submitted writes retain their transaction and rollback behavior. Any API `401` still locks the mounted document immediately.

On a focused return, pending intent survives loading/onboarding/save guards and resumes once eligible. Re-check eligibility before every fetch, after every awaited response, before every commit, and before follow-up alert/dependency work. Retire on user/workspace/auth-lock, scope/config revision, surface, or document-lifetime change. Do not replay missed timer intervals or an old-scope intent.

On BFCache restoration (`pageshow.persisted`), reevaluate current source check age/coverage and accepted catalog identity, then coalesce one intent if the check is unknown or older than the return threshold; execute only after the focused eligibility gate opens. A new/discarded document follows cache-first catalog/bootstrap authority and ordinary initial acquisition. Retained OS sleep is checked at the next observable focused/lifecycle return. An eventless wake of a continuously focused document has no guaranteed automatic trigger under this no-polling policy; do not claim fake-clock tests cover it.

Auth attempts use the current shell and DB token resolver; do not create a token store or bypass `apiFetch`. The shared auth timestamp records an **attempt**, not successful session renewal or an atomic cross-tab lock. Do not use it to label data fresh. Preserve one return intent across an in-flight/failed auth attempt and connection ownership; a later focused eligibility transition can retry through the existing throttle. Do not introduce background retry loops or promise a fresh session when only the timestamp was observed. Concurrent tabs may need their own data checks because their displayed snapshots differ.

### Viewed Epic first, then scope catch-up

1. Choose one reading anchor in the current surface: an open Epic detail or active issue interaction, then the last explicitly interacted visible Epic/Story, then the first visible real Story/Epic beneath the measured sticky controls. Pointer hover alone is not an intention. The anchor includes scope identity, Epic/Story key, actual scroll container, and its offset inside the visible region.
2. In Catch Up/Planning List and the compatible Planning table scope, acquire the anchor Epic's Product/Tech lanes with the existing `purpose=epic-refresh` route. Reuse keyed merging, local-edit fences and cap handling. Automatic mode omits manual button busy delay, glare, result announcements, and manual adoption analytics. A target that cannot be refreshed safely remains held; it does not block the broader check indefinitely.
3. After the anchor settles, run **one** ordinary scoped discovery pass (Product/Tech lanes). Collect results without clearing the mounted data/loading surface; reconcile keys and local mutation state. This pass finds new Epics/Stories and membership changes that per-Epic reads cannot discover. Do not issue one request per offscreen Epic. A capped/unknown response cannot remove unseen held members or settle completeness; mark coverage honestly.
4. Apply unaffected field updates by identity. Keep the anchor Epic's presented position and its current Story order for the reading session, even if canonical priority order changes. Store a bounded presentation exception for this one Epic, separate from source data. No fabricated Jira priority/status, persisted pin, or second ordering source for exports/calculations.
5. Release the presentation exception on explicit Refresh/sort, scope/surface change, or explicit navigation to another Epic. A scroll releases it only after the anchor has actually left its reading container's viewport; the refresh's own compensation cannot release it. Then use the current canonical order.

The intended guarantee is one retained reading context, not a frozen entire dashboard. Protect active filters, search text, expanded Epic/Story/Subtask state, selected Stories, sort/group choices, and mounted review drafts. If a refreshed item no longer matches the active filters/scope, do not silently reset those filters to keep it visible. Hold a clearly identified departing reading item only until the reading context is released; do not count it in authoritative totals, selection, export or writes. If access is revoked or an item is explicitly inaccessible, remove it immediately and use the nearest surviving same-container anchor; do not retain unauthorized content.

Before each commit recapture the current anchor and user-scroll generation. After settled layout, compensate in the **actual** container only when the user has not moved since capture. Prefer a surviving Story within the retained Epic, then its Epic, then the nearest surviving item, then the previous offset clamped to the available range. Account for changed height above/within the anchor and browser native anchoring; prove no double compensation. Never scroll the user back after they deliberately move, open a different item, or change scope while a request is running.

## Request and safety boundaries

One automatic generation per active scope. At most one targeted Epic job, then one broad scope job; each has at most two concurrent primary lane requests. Do not overlap the two stages or add an offscreen Epic fan-out. Share cancellation/deduplication with manual per-Epic work; explicit Refresh supersedes the automatic generation. Automatic primary work takes no new concurrency from initial bootstrap. Keep existing server pagination, caps, attempt/deadline/byte budgets and the independent Epic-refresh breaker; browser call counts do not bound Jira fan-out.

On `429`, keep held data and pending intent, honor `Retry-After`/existing retry budget, and permit at most one foreground deferred retry for the automatic generation. Cancel the retry on blur or scope change; no busy retry loop. On non-auth network/server failure, keep the snapshot and truthful check status. Connection recovery and terminal auth lock take precedence. Do not replay writes after sign-in.

No new route, credential, auth mode, CSRF exemption, workspace key or ownership migration is proposed. Implementation must inventory the following contracts and their adapter calls before coding:

| Existing route / transport | Contract to preserve |
| --- | --- |
| `POST /api/auth/refresh` | Existing auth-flow policy and requested-with header; no body/token exposure; successful JSON remains separate from data state; `401` terminal lock, other failure retains pending intent. |
| `GET /api/tasks-with-team-name` | Current request-auth/project-access guards; active group/Sprint, lane, Team/label scope and `refresh=true`. Targeted calls require one `epicKeys` value, numeric Sprint and `purpose=epic-refresh`. Preserve `{issues, epics, epicsInScope}` and existing targeted `{capped, epicKeysMissing}`; invalid requests fail 400, denied lanes remain denied, rate limit retains 429/`Retry-After`. |
| `GET /api/eng/board` | Server resolves authorized Department/workspace/project scope; existing `scope`, optional `sprintId`, `focusedColumnId`, `refresh=1`, NDJSON frames and auth/error terminal semantics. Do not graft Sprint-task responses onto strict Board authority. |
| `GET /api/sprints` and existing catalog completion reads | Keep workspace identity, accepted versions, same-attempt deadline and publication fence. Ordinary automatic data checks must not force catalog rediscovery. A long-return catalog read, if due under its own metadata, is a separate non-forced job after visible work; retain the selected Sprint while valid. A genuinely invalid Sprint requires clear scope-change guidance, not an unnoticed automatic switch. |
| Existing readiness, dependency, subtasks, review/capacity, Stats and EPM reads | Invoke only through the owning API/hook; retain current auth/CSRF/read guards, request shape, revision conflict and error contract. Follow-up work is surface-scoped and generation/focus guarded. A GET transport is not permission to change ownership. |

Jira enhanced issue search continues to use `nextPageToken` / `isLast`; Jira project search uses `startAt` / `isLast`. Do not treat an empty/capped page or failed lane as authoritative deletion. Required ownership reference: [`CONFIGURATION_OWNERSHIP.md`](../../backend/security/CONFIGURATION_OWNERSHIP.md). [GATE-05](GATE-05-home-write-capability.md) remains blocked and is not a prerequisite for this read-only feature.

## Acceptance criteria and negative tests

- Zero automatic Jira freshness requests start while hidden or visible-but-unfocused; delayed pre-blur responses and follow-up jobs cannot mutate the accepted view. Refocus coalesces one pending current-scope generation, including after a busy/save/bootstrap block ends.
- Zero freshness document/static-asset requests. Short return performs existing auth behavior without data acquisition. 8/24-hour returns check relevant data once, or show terminal auth recovery if the session cannot continue.
- On a targeted-compatible scope, the anchor Epic's primary requests precede broad primary requests and complete without clearing unrelated data. Strict Board instead prioritizes its focused column through the existing stream.
- Preserve the anchor Story/Epic at its prior container offset within 2 CSS pixels after settled layout when no user movement intervenes; verify changed-height and sorting cases, not just `scrollY`. Test independent Board panes and the Planning sheet's horizontal scroll.
- New priority order updates source values immediately; at most one reading Epic retains presentation order. Releasing it restores canonical order. No filter/search/Team/scope, expansion, selected-row, draft or editor reset; unchanged rows retain DOM identity.
- Partial/capped/failed sources cannot delete held members or advance a complete-scope status. Check timestamps remain source-specific. New remote members appear through broad discovery; moved/deleted/filtered anchor fallback and immediate access-revocation handling are explicit tests.
- Dirty review/schema/layout cells, local Story field inputs, pending/failed/rolled-back writes, Scenario drafts and Settings drafts survive. Existing conflict recovery remains deliberate; auto checks cannot update base revisions, save, discard, widen a write target or replay a failed write.
- Scope/config/workspace changes retire old results; rapid blur/refocus/manual Refresh races cannot add duplicate primary jobs. Concurrent-tab tests make only the deduplication claims they actually prove; session-attempt timestamps never become data-success timestamps.
- Non-auth failures retain held content and a retry path; `429` retry limits and cancellation hold. Any API `401` terminally locks all surfaces, including delayed/scoped requests, without local recovery UI or unlock in place.
- Initial startup request counts and first useful content do not regress. Catch Up alert fallbacks remain held until successful replacements; Board/Stats do not acquire Catch Up alerts. Cross-sprint authority/stream budgets and current pagination/source guards continue passing.
- Settled synthetic screenshots and element-level geometry assertions cover freshness copy, menu layering, anchored rows/panes and the existing sticky stacks at desktop and touch sizes. Preserve existing accessibility and tap support; new keyboard-only enhancements follow the repository's existing deferred policy.
