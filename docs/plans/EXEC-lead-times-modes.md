**Goal:** Statistics > Lead Times gets a single-select Mode dropdown (Created, Closed, Last N), each mode with its own selection control, and loses the Assignee filter.

**Architecture:** `POST /api/stats/epic-cohort` gains `mode`. `created` is today's code path, untouched, with a byte-identical request. `closed` and `last_n` use a new Component-scoped closed-status query whose orchestration lives in a pure module (`backend/services/epic_cohort_closed.py`, injected search and normalize callables) with a thin adapter in `jira_server.py`; `last_n` returns a bounded recent window and the client slices N after the filters. Mode and its selections live in the existing per-group stats state; share links gain two optional keys at `v=1`.

**Tech Stack:** Flask + `unittest` (`.venv/bin/python`), React 19 + esbuild, `node --test`, Playwright (Chromium; headed Firefox/WebKit where geometry changes).

## Global Constraints

- Closed = `Done`, `Killed`, `Incomplete`. `Postponed` is excluded from both closed modes entirely. Created mode is unchanged and keeps `Postponed` terminal with its chip.
- Closed-mode scope: exact Jira Component match (`component in (...)`, no Team clause) on `activeGroupMissingComponents` (the same source as the Board's `group.missingInfoComponents`); only when that list is empty, the Team clause of today's query with no `created` bound; when both are empty, or when `_cohort_project_scope()` is empty, no Jira search request and an empty result (`meta.scope = 'none'`; for no projects the same warning Created returns). No `OR key in (<ad hoc>)` widening in the closed modes; scope-matching Epics in the ad hoc list are still tagged `capacityType: "ad_hoc"`.
- Last N counts after the filters (Project, Exclude, status chips). N options exactly 30, 50, 60; default 30. Server window ceiling 200 (`EPIC_COHORT_LAST_N_WINDOW`, one source: `epic_cohort_closed.py`, clamped to at least 60). Changing N or any filter never refetches. Ranking: terminal day descending, then Epic key ascending, codepoint order on both client and server.
- Mode values exactly `created`, `closed`, `last_n`; default `created`. **The client omits `mode` for `created`** (the Created request body and the Created client cache key stay byte-identical; the smoke spec freezes exact bodies) and sends it for the closed modes. Server: absent `mode` = `created`; present but null, empty or unknown = 400.
- The Mode control is a `select.scenario-input` in a `.stats-control-group` (same kind as Project; it takes the slot the Assignee filter leaves). Measured on the real CSS at 966 px usable width: Created and Closed fit one row at 955.5 px (Mode 141, range 280, Group By 144, Project 141, Exclude 195); Last N fits one row at 811 px and the stretchy Mode and Number-of-epics selects widen to about 187 px each, moving Group By and Project about 46 px left. That flex is accepted. Row count and bar height must be equal in all modes at a 1280 px viewport; at narrower viewports labels must not clip or overflow (a changed row count is allowed there: measured 4 / 4 / 3 rows at 375 px).
- Heatmap in the closed modes: no `Open` column, no `In Progress` or `Postponed` chip, no Workflow Status card, no Open Epics chart; the `open` and `postponed` toggles are forced off in the filter; overflow column `Q+12+` / `M+24+` (budget 12 quarters / 24 months; regular columns `0..R`, overflow holds elapsed ≥ B); rows span the earliest to the latest created period of the displayed Epics.
- Stale data: the derived layer uses `cohortData` only when `(meta.mode ?? 'created') === cohortMode`; a mismatch is the explicit `cohortAwaitingMode` state (panel shows the loading line; Project and selected-row prune effects, warnings and the empty message are all held while it is true).
- Jira links: Created frozen (only the assignee clause goes); closed modes link `key in (...)` of the Epics the chart lists, hidden above 250 keys with a `.stats-note` saying why.
- No new CSS classes: reuse `.stats-control-group`, `.controls-label`, `select.scenario-input`, `StatsRangeControl`, `SegmentedControl` + `eng-mode-control` (Group By only), `.stats-note`, `.cohort-empty`. A new class for an existing control kind is a review-stop (register anything genuinely new in `docs/design-system.md` and the ratchet allowlists).

Pagination: `nextPageToken` / `isLast`. One shared page counter (80 pages) bounds the whole closed request across passes and batches.

## Review Focus

Inputs the spec implies and no happy path covers; each has a pinned test in the named task.

1. An Epic created many periods before it closed lands in the overflow column and the grid still renders (Task 5, Task 10).
2. A closed-status Epic with no `resolutiondate` whose changelog is partial, capped or failing: never silently dropped; a failed Jira pass is an error, not a warning; warning shown for caps; excluded from the last-N ranking (Task 2).
3. Postponed or open Epics, even if they once closed, never appear in a closed mode, including with a persisted `postponed: true` toggle (Task 2, Task 5, Task 10).
4. Stale or invalid saved values and links: a saved `cohortAssigneeFilter`, an unknown mode, `N=45`; `lead=foo`, `n=7`, `lead=last_n` without `n` (Task 4, Task 6, Task 9).
5. Empty and in-between states: no Components and no Teams, no projects, no closed Epics in the window, filters removing everything in Last N, and another mode's data still in memory when the mode changes, including the Project filter surviving Created → Closed → Created (Task 2, Task 6, Task 7, Task 10).

Also covered: MRT018 long lists (Task 10), Component names with quotes through `_escape_jql_literal` (Task 2), MRT031 continuation-token sizing (Task 2), OAuth worker-thread context (Task 2).

### Task 1: Jira probe gate (read-only, numbers only)

**Files:** none; counts and timings go into Execution status only.

The closed query needs three JQL shapes to parse on the real instance, and the number of Epics that need a changelog lookup (one request each, 4 workers, 10 s budget) must fit the budget.

- [ ] **Step 1: Probe** with the Basic-auth service credentials in the local `.env.backup_basic` (never through the app's OAuth store). Using the real Department Component scope, record **counts, timings and yes/no only**; keep no keys, names or payloads, delete scratch output. `S` = `("Done","Killed","Incomplete")`, `d1`/`d2` = bounds of the most recent full quarter.
  1. `issuetype = Epic AND component in (<scope>) AND status in S AND resolutiondate is EMPTY` parses (this also proves the three status names exist on the instance); `U_all` = count.
  2. The bound used for `closed`: the same query plus `AND (status CHANGED TO "Done" DURING ("<d1 - 1 day>","<d2 + 2 days>") OR ... "Killed" ... OR ... "Incomplete" ...)` parses; `U_q` = count.
  3. The bound used for `last_n`: the same plus `AND (status CHANGED TO "Done" AFTER "<d1 - 1 day>" OR ...)`; `U_b` = count.
  4. The resolved forms parse: `... AND resolutiondate >= "<d1 - 1 day>" AND resolutiondate < "<d2 + 2 days>"` (count `R`) and `... AND resolutiondate is not EMPTY ORDER BY resolutiondate DESC` (are the first page's `resolutiondate` values non-increasing: yes/no).
  5. Latency: 10 sequential `GET /rest/api/3/issue/<key>?fields=status&expand=changelog` for unresolved Epics: p50 seconds, how many have `changelog.total` greater than the embedded `histories`, and the p50 of the extra `/changelog` page request for those.

### Task 2: Closed-mode query, selection and fetch

**Files:**
- Create: `backend/services/epic_cohort_closed.py`, `tests/test_epic_cohort_closed.py`
- Modify: `jira_server.py` (`fetch_epic_cohort_data` ~5124, `_cohort_fetch_terminal_date_from_changelog` ~5107), `tests/test_epic_cohort_api.py`, `tests/test_codebase_structure_budgets.py`

**Interfaces (produces):**
- In `backend/services/epic_cohort_closed.py` (pure, no I/O):
  - `CLOSED_EPIC_STATUSES = ('Done', 'Killed', 'Incomplete')`; `LAST_N_WINDOW = max(60, int(os.getenv('EPIC_COHORT_LAST_N_WINDOW', '200')))`; `MAX_TOTAL_PAGES = 80`; `class EpicCohortScopeError(ValueError)`; `class EpicCohortSearchError(Exception)` carrying `.response` (the failed Jira response).
  - `build_closed_epic_jqls(project_clause: str, scope_clause: str, *, mode: str, start_date: date | None, end_date: date | None, unresolved_since: date | None = None) -> dict[str, str]` returning `{'resolved': jql, 'unresolved': jql}`. Both start `issuetype = Epic AND project in (...)`, add the scope clause and `status in ("Done","Killed","Incomplete")`. `resolved` for `closed` adds `resolutiondate >= "<start - 1 day>" AND resolutiondate < "<end + 2 days>"` (one-day widening each side; the post-filter makes it safe); for `last_n` adds `resolutiondate is not EMPTY ORDER BY resolutiondate DESC`. `unresolved` adds `resolutiondate is EMPTY` and a status-history bound: for `closed` `(status CHANGED TO "Done" DURING ("<start - 1 day>","<end + 2 days>") OR ... Killed ... OR ... Incomplete ...)`; for `last_n` the same with `AFTER "<unresolved_since>"` when given, none when not. No order on `unresolved`.
  - `scope_batches(components: Sequence[str], build_pair: Callable[[Sequence[str], date | None], dict[str, str]], fields: Sequence[str]) -> list[tuple[str, ...]]`: Components are batched with `eng_board.split_component_batches` sizing the **longer** JQL of each pair built with a fixed-width placeholder `unresolved_since`; an empty `components` (Teams scope) returns `[()]` after the same size check; any `EngBoardError` or oversize becomes `EpicCohortScopeError`.
  - `select_closed_epics(issues: list[dict], *, mode: str, start_date: date | None, end_date: date | None, ceiling: int) -> tuple[list[dict], bool]`: from normalized Epics, drops any whose `status` is not in `CLOSED_EPIC_STATUSES` or that lack `terminalDate`; `closed` keeps `start_date <= terminalDate <= end_date` and is never trimmed (`ceiling` ignored); `last_n` sorts by the parsed terminal day descending then `key` ascending (codepoint order) and keeps `ceiling`; returns `(kept, trimmed)`.
  - `fetch_closed_epics(search_pages, normalize, *, mode, start_date, end_date, batches, make_pair, ceiling, warnings: list[str]) -> dict`. `search_pages(jql, *, max_rows=None) -> (rows, stop)` where `stop` is `'done' | 'max_rows' | 'page_cap'`, **raises `EpicCohortSearchError` on any non-200** and draws from one shared page counter (`MAX_TOTAL_PAGES`). Order: every batch's `resolved` pass first (for `last_n` each stops after `ceiling + 1` rows, then continues until the resolution day differs from the `ceiling`-th row's day, bounded by the page counter, so the cut falls on a day boundary); merge by key; derive `unresolved_since` (`last_n`: the day before the `ceiling`-th merged resolution day when merged rows exceed `ceiling`, else `None`); run the `unresolved` passes; merge; `normalize(rows) -> (issues, truncated)`; `select_closed_epics`. `warnings` is the single list the adapter also hands to `normalize`. Returns `{'issues': [...], 'windowFull': bool | None, 'truncated': bool, 'warnings': warnings}`: `windowFull` is `None` for `closed`, and for `last_n` true when more closed Epics exist beyond the ceiling; `truncated` is true only for `'page_cap'` or a normalizer cap, never for the expected `max_rows` stop.
- In `jira_server.py`:
  - `_normalize_cohort_issues(all_issues, headers, team_field_id, ad_hoc_key_set, context, warnings, *, today, truncated=False, full_changelog=False) -> tuple[list[dict], bool]`: the changelog enrichment and normalization tail extracted from `fetch_epic_cohort_data`; the returned flag is the incoming `truncated` OR anything the tail sets (assignment would overwrite the page-cap flag). `today` is passed in; the tail never reads the clock.

Issue objects are exactly the fields `fetch_epic_cohort_data` emits.
