**Goal:** Statistics > Lead Times gets a single-select Mode dropdown (Created, Closed, Last N), each mode with its own selection control, and loses the Assignee filter.

**Architecture:** `POST /api/stats/epic-cohort` gains `mode`. `created` is today's code path, untouched, with a byte-identical request. `closed` and `last_n` use a new Component-scoped closed-status query whose orchestration lives in a pure module (`backend/services/epic_cohort_closed.py`, injected search and normalize callables) with a thin adapter in `jira_server.py`; `last_n` returns a bounded recent window and the client slices N after the filters. Mode and its selections live in the existing per-group stats state; share links gain two optional keys at `v=1`.

**Tech Stack:** Flask + `unittest` (`.venv/bin/python`), React 19 + esbuild, `node --test`, Playwright (Chromium; headed Firefox/WebKit where geometry changes).

## Global Constraints

- Closed = `Done`, `Killed`, `Incomplete`. `Postponed` is excluded from both closed modes entirely. Created mode is unchanged and keeps `Postponed` terminal with its chip.
- Closed-mode scope: exact Jira Component match (`component in (...)`, no Team clause) on `activeGroupMissingComponents` (the same source as the Board's `group.missingInfoComponents`); only when that list is empty, the Team clause of today's query with no `created` bound; when both are empty, or when `_cohort_project_scope()` is empty, no Jira search request and an empty result (`meta.scope = 'none'`; for no projects the same warning Created returns). No `OR key in (<ad hoc>)` widening in the closed modes; scope-matching Epics in the ad hoc list are still tagged `capacityType: "ad_hoc"`.
- Last N counts after the filters (Project, Exclude, status chips). N options exactly 30, 50, 60; default 30. Server window ceiling 200 (`EPIC_COHORT_LAST_N_WINDOW`, one source: `epic_cohort_closed.py`, clamped to at least 60). Changing N or any filter never refetches. Ranking: terminal day descending, then Epic key ascending, codepoint order on both client and server.
- Mode values exactly `created`, `closed`, `last_n`; default `created`. **The client omits `mode` for `created`** (the Created request body and the Created client cache key stay byte-identical; the smoke spec freezes exact bodies) and sends it for the closed modes. Server: absent `mode` = `created`; present but null, empty or unknown = 400.
- The Mode control is a `select.scenario-input` in a `.stats-control-group` (same kind as Project; it takes the slot the Assignee filter leaves). Measured on the real CSS at 966 px usable width: Created and Closed fit one row at 955.5 px (Mode 141, range 280, Group By 144, Project 141, Exclude 195); Last N fits one row at 811 px and the stretchy Mode and Number-of-epics selects widen to about 187 px each, moving Group By and Project about 46 px left. That flex is accepted. Row count and bar height must be equal in all modes at a 1280 px viewport; at narrower viewports labels must not clip or overflow (a changed row count is allowed there: measured 4 / 4 / 3 rows at 375 px).
- Heatmap in the closed modes: no `Open` column, no `In Progress` or `Postponed` chip, no Workflow Status card, no Open Epics chart; the `open` and `postponed` toggles are forced off in the filter; overflow column `Q+12+` / `M+24+` (budget 12 quarters / 24 months; regular columns `0..R`, overflow holds elapsed ≥ B); rows span the earliest to the latest created period of the displayed Epics.
- Stale data: the derived layer uses `cohortData` only when `(meta.mode ?? 'created') === cohortMode`; a mismatch is the explicit `cohortAwaitingMode` state (panel shows the loading line; Project and selected-row prune effects, warnings and the empty message are all held while it is true).
- Jira links: Created frozen (only the assignee clause goes); closed modes link `key in (...)` of the Epics the chart lists, hidden above 250 keys with a `.stats-note` saying why.
- No new CSS classes: reuse `.stats-control-group`, `.controls-label`, `select.scenario-input`, `StatsRangeControl`, `SegmentedControl` + `eng-mode-control` (Group By only), `.stats-note`, `.cohort-empty`. A new class for an existing control kind is a review-stop (register anything genuinely new in `docs/design-system.md` and the ratchet allowlists).
- Jira search is GET `/rest/api/3/search/jql` (`current_jira_search`): every JQL is sized by `paged_search_bytes` (MRT031), including the Teams scope and the bound clause added later; Components are batched with `split_component_batches` sizing the **longer** JQL of the resolved/unresolved pair built with a fixed-width placeholder date; never lengthen a query to filter rows the code already discards. Pagination: `nextPageToken` / `isLast`. One shared page counter (80 pages) bounds the whole closed request across passes and batches.
- Structure budgets: `jira_server.py` has 28 lines of headroom (6459 of 6487) and `dashboard.jsx` sits exactly at its ceiling (7569) in both `tests/test_codebase_structure_budgets.py` and `scripts/extraction_lint/owner_budgets.json`. ## Review Focus

Inputs the spec implies and no happy path covers; each has a pinned test in the named task.

1. An Epic created many periods before it closed lands in the overflow column and the grid still renders (Task 5, Task 10).
2. A closed-status Epic with no `resolutiondate` whose changelog is partial, capped or failing: never silently dropped; a failed Jira pass is an error, not a warning; warning shown for caps; excluded from the last-N ranking (Task 2).
3. Postponed or open Epics, even if they once closed, never appear in a closed mode, including with a persisted `postponed: true` toggle (Task 2, Task 5, Task 10).
4. Stale or invalid saved values and links: a saved `cohortAssigneeFilter`, an unknown mode, `N=45`; `lead=foo`, `n=7`, `lead=last_n` without `n` (Task 4, Task 6, Task 9).
5. Empty and in-between states: no Components and no Teams, no projects, no closed Epics in the window, filters removing everything in Last N, and another mode's data still in memory when the mode changes, including the Project filter surviving Created → Closed → Created (Task 2, Task 6, Task 7, Task 10).

Also covered: MRT018 long lists (Task 10), Component names with quotes through `_escape_jql_literal` (Task 2), MRT031 continuation-token sizing (Task 2), OAuth worker-thread context (Task 2).
