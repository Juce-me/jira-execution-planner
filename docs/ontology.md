## Department Configuration

Verified on: 2026-09-25.

- **Department group label mapping**: workspace-shared mapping from each configured Jira Team id to one to three Jira Epic-label aliases (`Record<TeamId, JiraLabel[]>`, payload version 2) currently used to discover and classify that Team's Epics; any one of a Team's aliases matches. Canonical storage is the `teamLabels` field inside `workspace_group_configs.payload` in DB/OAuth mode and the equivalent `teamGroups` JSON payload in local/basic mode; ownership contract: `backend/security/CONFIGURATION_OWNERSHIP.md`; normalization, bounds, duplicate detection, and flattening: `backend/services/team_catalog.py`; validation integration and JQL-scope building: `backend/services/group_config.py`; version constants: `GROUPS_PAYLOAD_VERSION` / `GROUP_PREFERENCES_PAYLOAD_VERSION` in `backend/services/shared_group_config.py` and `GROUPS_CONFIG_VERSION` in `jira_server.py`; routes: `GET/POST /api/groups-config` in `backend/routes/settings_routes.py`; frontend normalization/editor: `frontend/src/settings/groupConfigUtils.js` (canonical helpers, `GROUPS_CONFIG_VERSION`) and `frontend/src/dashboard.jsx` (multi-chip editor, up to three aliases); contracts: `tests/test_team_catalog_service.py`, `tests/test_group_config_service.py`, `tests/test_shared_group_config_service.py`, `tests/test_group_config_utils.js`, and `tests/ui/shared_department_groups.spec.js`. Legacy scalar values (DB rows, JSON files, environment JSON, backend import, Settings JSON import) normalize to one-item arrays on read with no write.
- **Task-route alias resolution**: `fetch_tasks` in `jira_server.py` resolves the Department's saved aliases through `shared_group_config.load_effective_groups` (the same effective-groups seam Story readiness uses) before `build_tasks_cache_key`, merges them with request-supplied aliases, de-duplicates case-insensitively, and uses that set for both the `/api/tasks-with-team-name` cache key and the Jira JQL built by `backend/services/group_config.build_epic_alert_scope_clause` (labels escaped via `backend.services.alert_epics.quote_jql_value`). This means a saved-alias change changes the next task response even with an unchanged browser query string. It depends on the Department group label mapping above and on `backend/services/alert_epics.py` (`AlertEpicScopeTooLarge`, mapped to an uncached `422 alert_scope_too_large`); it produces the alert-scope Epic set consumed by future-planning alerts (`frontend/src/futurePlanningTeamUtils.mjs`, `frontend/src/eng/engTaskUtils.js`) and the oversized-Department notice in `frontend/src/eng/EngAlertsPanel.jsx`. Contracts: `tests/test_create_stories_alert.py`, `tests/test_oauth_eng_routes.py`.
- **Story readiness relationship**: `_story_readiness_group_snapshot` in `backend/routes/eng_routes.py` reads the same alias arrays into the `{"labels": [...]}` shape consumed by `backend/services/story_readiness.py`, which matches any alias per Team exactly once and still fails closed (`story_readiness_configuration_invalid`) when an alias is shared by two Teams. ## Connection Recovery

Verified on: 2026-09-23.

Verified on 2026-09-24.
- **Connection recovery capsule**: strict 30-minute `sessionStorage` record containing principal, shell position, a Settings-discard notice flag, and optionally canonical dirty Scenario overrides. It never owns Settings values or EPM state. Canonical Scenario override normalization is in `frontend/src/scenario/scenarioDraftOverrides.js`; contract coverage is in `tests/test_connection_recovery_state.js` and `tests/test_scenario_draft_overrides.js`.

It has precedence over connection recovery. `frontend/src/api/authFocusRefresh.js` consumes connection availability events from `frontend/src/api/authRefreshContract.js` so focus/long-absence refresh cannot race a recovery reload.
- **Scenario recovery compute**: one fresh compute-only `POST /api/scenario` plus active-draft read after exact group/sprint restoration. `frontend/src/scenario/connectionScenarioRecovery.js` binds recovery to the stored draft scope and overlays only the captured local delta onto the fresh server baseline. It never replays Scenario save, publish, rollback, reload-from-Jira, or Jira mutations.

## Workspace identity and shared catalogs

Verified on: 2026-09-22 against the current source paths and tests named below, except the Sprint catalog entry reviewed on 2026-09-23. Workspace meaning and sharing were confirmed on 2026-09-13; persistent Sprint and per-Sprint Team storage is now implemented locally on this branch.

- **Workspace** (domain aliases: Jira identity, Jira site, Jira domain): the Jira site shared by the entity within one configured application environment. All authenticated users resolved to that environment/site belong to the same catalog scope. The canonical implementation key is `RequestAuthContext.workspace_id`, not a user, OAuth connection, token version, or Department. [`Workspace`](../backend/db/models.py) has unique environment/cloud-ID and environment/site-URL indexes; [`stable_local_workspace_id`](../backend/auth/context.py) uses the environment plus cloud ID, falling back to normalized site URL. [`resolve_db_request_auth_context`](../backend/auth/db_context.py) connects authenticated identity to the persisted workspace. Reuse this resolution rather than inventing a new browser-supplied domain key. Different environments or Jira sites remain isolated. Evidence/tests: [`test_auth_context.py`](../tests/test_auth_context.py), [`test_auth_context_db.py`](../tests/test_auth_context_db.py), [`test_db_migrations.py`](../tests/test_db_migrations.py).
- **Workspace catalogs**: shared derived Jira metadata for one workspace. [`WorkspaceSprintCatalog`](../backend/db/models.py) is keyed by workspace + Jira source Board; [`WorkspaceSprintTeamCatalog`](../backend/db/models.py) is keyed by workspace + Sprint and binds validated membership to an effective-scope digest; [`WorkspaceTeamCatalog`](../backend/db/models.py) is the independent workspace Team-name directory. All authenticated users in the same workspace consume the same saved lists. The refreshing user's identity is authentication/audit context, not catalog ownership or a cache partition. Relationships: consumes effective workspace Jira configuration and authenticated Jira reads; produces Sprint choices, Sprint-scoped Team availability, and Team labels. Tests: [`test_workspace_catalog_cache.py`](../tests/test_workspace_catalog_cache.py), [`test_persistent_catalog_routes.py`](../tests/test_persistent_catalog_routes.py), and [`test_workspace_catalog_postgresql.py`](../tests/test_workspace_catalog_postgresql.py); ownership: [configuration ownership](../backend/security/CONFIGURATION_OWNERSHIP.md).
- **Effective catalog configuration and publication fence**: [`resolve_effective_catalog_config`](../backend/services/workspace_catalog_config.py) consumes saved Board/projects/Team and Sprint fields plus environment-priority base JQL, preserving revision-zero exact-site fallback. [`claim_catalog_refresh`](../backend/services/workspace_catalog_cache.py) and [`publish_catalog`](../backend/services/workspace_catalog_cache.py) share [`acquire_workspace_config_fence`](../backend/services/workspace_dashboard_config.py) with administrator/capacity updates and legacy promotion. Publication re-resolves the configuration and locks the refresh actor's BrowserSession before replacing a complete payload; Team publication also updates discovered names atomically. A changed identity/scope or retired actor cannot publish. [`CatalogRefreshRuntime`](../backend/services/catalog_refresh_runtime.py) owns the two-worker bounded runtime, attempt deadline, lease, and failure classification. Relationships: configuration determines identity; fenced publication produces complete membership and version metadata; completion reads consume only the named attempt and identity.
- **Unconfigured-workspace gate** (verified 2026-09-28; aliases: dropped admin settings, unconfigured dashboard): [`resolve_effective_catalog_config`](../backend/services/workspace_catalog_config.py) reports `missing_admin_settings` (`scope` without selected projects or `JQL_QUERY`, `source` without a numeric Jira source Board). DB/OAuth `GET /api/config` in [`settings_routes.py`](../backend/routes/settings_routes.py) returns it as `adminSettingsMissing`, plus `adminContacts` (tool-admin display names from [`workspace_tool_admin_display_names`](../backend/auth/admin_bootstrap.py)) for non-editors only. [`useAdminSettingsGate`](../frontend/src/settings/adminSettingsGate.js) holds the gate; `frontend/src/dashboard.jsx` starts Sprint discovery, Board, cohort, and excluded-capacity reads only once the gate is `clear`, opens Admin settings for editors, and renders [`UnconfiguredWorkspaceNotice`](../frontend/src/settings/UnconfiguredWorkspaceNotice.jsx). Relationships: depends on effective catalog configuration; blocks Sprint catalog reads; the user directory (`/api/admin/users*`) stays tool-admin only. Tests: `tests/test_unconfigured_workspace_gate.py`, `tests/test_admin_settings_gate.js`, `tests/ui/unconfigured_workspace_gate.spec.js`.
- **User authorization and preferences**: credentials authorize upstream requests; private preferences remain user-owned. Sharing these catalogs does not change the ownership of issue payload caches, personal connections, saved private views, or Department configuration. Complete refresh results replace the shared catalog under the plan's lease/completeness rules; this is shared metadata, not a per-reader reconstruction of Jira visibility.

Tests: [`eng_group_board_view.spec.js`](../tests/ui/eng_group_board_view.spec.js) ("pane mode" and small-screen alert tests), [`test_analytics_events.js`](../tests/test_analytics_events.js) (`board_action` builder and schema).
