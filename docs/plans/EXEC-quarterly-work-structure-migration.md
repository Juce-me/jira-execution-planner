**Goal:** Resolve workspace project configuration from the viewed quarter, preserve Legacy behavior and move quarterly planning one Jira level higher. Project configuration, work configuration, work structure and Project config tab name this same feature. `DELIVERY` is an editable display name, `delivery` below is a synthetic opaque configuration id, and `PLAN` is a synthetic Jira project key.

**Architecture:** One revisioned DB workspace bundle; one immutable request context; two explicit adapters, `legacy|rnd_2027`; existing Flask/SQLAlchemy/Alembic and React 19/esbuild with Node 20, no dependency. Supported feature runtime is **DB-backed OAuth only**. No dedicated JSON/Basic removal execution plan was found; establish that separately owned prerequisite before rollout, rather than implementing it in this feature.

## Decisions and exact UI contract

The viewed Sprint is a quarter. Initial Legacy is open-start through `2026Q4`; DELIVERY is `2027Q1` through open-end, inclusive. Ranges remain editable. Exactly these two ordered configurations are supported: Legacy must precede DELIVERY regardless of display name; reject swapped models/order, gaps, overlaps, invalid start/end, duplicate ids/names and finite outer bounds. Accept strict unpadded uppercase `YYYYQ[1-4]`, calendar years `0001`–`9999`; reject lowercase, whitespace, `0000` and five-digit years instead of normalizing. The calendar bound follows current `date(year,...)` use (`jira_server.py:1065–1079`), not a business forecasting limit. Moving a boundary changes which configuration live views use; saved review namespaces are not reassigned.

## Runtime, storage and errors

Create `backend/services/work_structure.py` with `normalize_work_configurations`, `resolve_work_configuration(snapshot, *, quarter, configuration_id=None)`, `project_legacy_admin_settings(context)` and `save_work_configurations(context,bundle,base_revision)`. Immutable `WorkConfigurationContext` contains id/revision/model/quarter/digest/scope/hierarchy/fields, no Capacity. A request captures it once and passes it through worker/no-request-context helpers. Supplied id must agree with viewed quarter; cross-quarter reports resolve each quarter. All-work/backlog/Component views use the accepted dashboard quarter, not the calendar date; the quarter selects their configuration even when the existing mode has no physical Sprint predicate.

Server flag `WORK_CONFIGURATIONS_ENABLED` defaults off. Before promotion, flag-off ignores seeded unpromoted bundle data, keeps the existing flat Admin editor/Save and Legacy reads, and denies feature POST with `409 configuration_feature_disabled`. After promotion, flag-off returns that same error for structural work reads and feature writes, shows scoped unavailable guidance and never reactivates old flat/environment readers. It is not a rollback switch. The durable server-owned `promotionRevision` makes this distinction across worker/process restarts; current workspace revision alone is insufficient because other settings share it (`backend/db/models.py:246–258`, `backend/services/workspace_dashboard_config.py:164–218`). Final Task 6 enables only after every reader is quarter-aware and the promoted-path bypass allowlist is empty. No UI activation lifecycle. `promotionRevision` is internal immutable migration metadata, never a browser-controlled action. The full editable-bundle serializer omits it; an unchanged read-only echo may be ignored, but attempted changes/import overrides are rejected. An absent marker means unpromoted; only the fenced first-save transaction may set it. Later configuration or unrelated settings revisions never change it. Once enabled and promoted, a no-quarter structural getter fails **409 `configuration_required`**, never silently chooses Legacy. Bootstrap `/api/config` is the intentional no-quarter metadata endpoint; it does not call a moved-key getter. It adds explicit boolean `workConfigurationsEnabled` / `workConfigurationsPromoted`, compact `workConfigurationSummaries` (id/name/revision/model/ranges) and `adminSettingsMissingByConfiguration`. After promotion it omits unscoped projects/Board/field/issue-type projections; consumers must wait for an admitted quarter context. Keep existing global Capacity/weights/edit grants/private bootstrap data. Settings/type/Test/catalog metadata reads with an explicit configuration id inspect that stored entry directly; they do not authorize a quarter-less work query or call a moved structural getter. New feature routes/readers outside DB/OAuth return **409 `work_configuration_setup_required`**, no JSON/Basic/service/local-token fallback. Broader extraction remains outside this plan.

The current updater writes one section (`workspace_dashboard_config.py:164–218`). Add one dedicated DB multi-key operation: acquire existing workspace advisory fence, load/recheck revision, recapture first-save input, validate, replace bundle/remove moved keys, increment changed entry revisions and global revision once, audit/commit. Reuse the fence for catalog claim/publication. Preserve other owner's payload and verification columns; never expose full-workspace replacement. Renaming alone increments entry revision and stale in-flight writes. Keep mine uses whole-bundle CAS against the newly read global revision, subject to current shape and monotonic-authority validation; show that a valid retry replaces remote bundle edits but cannot bypass validation/concurrency. Reload replaces selected saved drafts only after existing dirty confirmation.

Success `200 {workConfigurations,configRevision,changedConfigurationIds,promoted:true}`; normalized saved Legacy entries include the durable slot modes. Conflict `409 {error:"workspace_config_conflict",configRevision,workConfigurations}` includes complete current bundle. Other safe errors: `400 invalid_work_configurations/invalid_quarter/invalid_configuration_id/ambiguous_configuration_scope`; `403 admin_required/csrf_required`; `409 configuration_incomplete/configuration_scope_changed/sprint_catalog_mismatch/configuration_bundle_required/configuration_required`; `503 config_storage_unavailable/catalog_storage_unavailable`. Do not return Jira payloads/JQL/raw exception text. Unknown property names, malformed identifier syntax and browser-supplied authority are rejected before mutation. A syntactically valid but unresolved saved Jira type/field id is retained as incomplete, not rejected merely because the current catalog cannot resolve it. Existing application 401 terminally locks the mounted app; preserve drafts, no local recovery or replay. A 403 is not sign-in recovery.

The project bundle and its promotion marker use the existing workspace payload; no new project-config table is needed; review storage below does require one. Rollback preflight `scripts/check_work_configuration_rollback.py` reads the selected workspace's **DB row read-only**, not a sanitized config file; it refuses **any promoted bundle**, even incomplete. An old binary cannot protect itself: deployment must run this newer preflight and use a separately verified DB restoration transaction before downgrade. No automatic flattening or mutation by the checker. Forward rollback preserves data and fails closed on unsupported adapter. Review downgrade checks are separate.
