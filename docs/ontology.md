# Project Ontology

Coverage: verified entry points and relationships for Statistics (2026-09-10), ENG Board cross-sprint loading, availability, and operational measurement (2026-09-12), and workspace/catalog ownership (2026-09-13). Other application areas remain unmapped.

## Workspace identity and shared catalogs

Verified on: 2026-09-13. Workspace meaning and catalog sharing explicitly confirmed by the user on this date; persistent Sprint and per-Sprint Team storage remains planned.

- **Workspace** (domain aliases: Jira identity, Jira site, Jira domain): the Jira site shared by the entity within one configured application environment. All authenticated users resolved to that environment/site belong to the same catalog scope. The canonical implementation key is `RequestAuthContext.workspace_id`, not a user, OAuth connection, token version, or Department. [`Workspace`](../backend/db/models.py) has unique environment/cloud-ID and environment/site-URL indexes; [`stable_local_workspace_id`](../backend/auth/context.py) uses the environment plus cloud ID, falling back to normalized site URL. [`resolve_db_request_auth_context`](../backend/auth/db_context.py) connects authenticated identity to the persisted workspace. Reuse this resolution rather than inventing a new browser-supplied domain key. Different environments or Jira sites remain isolated. Evidence/tests: [`test_auth_context.py`](../tests/test_auth_context.py), [`test_auth_context_db.py`](../tests/test_auth_context_db.py), [`test_db_migrations.py`](../tests/test_db_migrations.py).
- **Workspace catalogs**: shared derived Jira metadata for that workspace. The Sprint catalog belongs to workspace + Jira source Board; per-Sprint Team membership belongs to workspace + Sprint, validated against the effective Board/project/query/Team-field scope; the global Team name directory belongs to the workspace. All users in the same workspace consume the same saved lists. Refreshing user's identity is authentication/audit context, not catalog ownership or a cache partition. A user signing out, reconnecting, or refreshing a token does not erase these shared catalogs. Relationships: consumes workspace Jira configuration and authenticated Jira reads; produces Sprint choices, Team availability, and Team labels. Contract and planned tests: [persistent catalog plan](plans/EXEC-persistent-sprint-team-catalogs.md); current name-directory ownership: [configuration ownership](../backend/security/CONFIGURATION_OWNERSHIP.md).
- **User authorization and preferences**: credentials authorize upstream requests; private preferences remain user-owned. Sharing these catalogs does not change the ownership of issue payload caches, personal connections, saved private views, or Department configuration. Complete refresh results replace the shared catalog under the plan's lease/completeness rules; this is shared metadata, not a per-reader reconstruction of Jira visibility.

## ENG Board cross-sprint loading

Verified on: 2026-09-12 against the local issue #190 follow-up implementation on `bugfix/board-progressive-loading`, from baseline `40bffe7`; the implementation is local and unpublished. Ownership is described as implementation responsibility, not an undocumented team assignment.

- **ENG Board** (UI aliases: Board, Kanban): Epic columns rendered by [`EngBoardView`](../frontend/src/eng/EngBoardView.jsx). Contract: [ENG workflows](features/eng-workflows.md#board-kanban). Ordinary Sprint mode consumes the already-loaded Catch Up snapshot through [`dashboard.jsx`](../frontend/src/dashboard.jsx); only cross-sprint Component/All work uses the strict owner. All ENG work waits for a non-empty Sprint catalog; a saved Sprint label is display-only until that catalog validates it. Cross-sprint availability then depends on server capability, Department Board columns, and persisted Jira authority from saved selected projects or a saved Jira source Board. Backend capture resolves and access-checks the saved authority. Tests: [`eng_group_board_view.spec.js`](../tests/ui/eng_group_board_view.spec.js), [`test_eng_board_routes.py`](../tests/test_eng_board_routes.py), [`test_eng_board_service.py`](../tests/test_eng_board_service.py).
- **Sprint catalog**: quarterly Sprint values returned by `GET /api/sprints` in [`settings_routes.py`](../backend/routes/settings_routes.py). Basic mode keeps the existing file cache; OAuth mode uses `SPRINTS_PROCESS_CACHE`, keyed by the authenticated Jira/Home cache partition and saved Jira Board, for 24 hours. Cache misses use [`fetch_sprints_from_jira`](../backend/services/sprints.py); empty or failed catalogs keep ENG data gated. Auth/config invalidation clears the process cache. Tests: [`test_oauth_stats_routes.py`](../tests/test_oauth_stats_routes.py), [`test_cache_partitioning.py`](../tests/test_cache_partitioning.py), [`eng_group_board_view.spec.js`](../tests/ui/eng_group_board_view.spec.js). Reviewed 2026-09-13 against the working checkout; [persistent catalog plan](plans/EXEC-persistent-sprint-team-catalogs.md) has confirmed workspace-shared ownership but requires four execution-contract amendments from the fresh review before implementation; the current user-partitioned Sprint process cache is the migration source, not the target ownership contract.
- **Team name directory and Sprint discovery** (verified 2026-09-13): `GET/POST /api/team-catalog` in [`settings_routes.py`](../backend/routes/settings_routes.py) delegates DB names to `load_workspace_team_catalog` / `save_workspace_team_catalog` in [`workspace_dashboard_config.py`](../backend/services/workspace_dashboard_config.py), backed by `WorkspaceTeamCatalog` in [`models.py`](../backend/db/models.py). Ownership: workspace-shared derived names per [configuration ownership](../backend/security/CONFIGURATION_OWNERSHIP.md). Current `get_teams` in [`eng_routes.py`](../backend/routes/eng_routes.py) discovers Teams from issues; `all=true` also unions global registry results and can fall back beyond the selected Sprint. Settings `loadTeamCatalog`, `fetchAllTeamsFromJira` and `resolveMissingTeamNames` in [`dashboard.jsx`](../frontend/src/dashboard.jsx) currently conflate names and availability. Tests: [`test_team_catalog_api.py`](../tests/test_team_catalog_api.py), [`test_oauth_stats_routes.py`](../tests/test_oauth_stats_routes.py). The [persistent catalog plan](plans/EXEC-persistent-sprint-team-catalogs.md) proposes separating these concepts; no per-Sprint membership table exists yet.
- **Component scope**: exact Department `missingInfoComponents` matched on Epic Components, across sprints. [`iter_strict_search_pages`](../backend/services/eng_board.py) validates each Jira page; [`iter_component_epic_batches`](../backend/services/eng_board.py) produces cumulative validated membership and a final marker consumed by [`_frame_stream`](../backend/routes/eng_board_routes.py). Candidate delivery is page-progressive but bounded/coalesced on the wire. Tests: [`test_eng_board_progressive_loading.py`](../tests/test_eng_board_progressive_loading.py), [`eng_board_progressive_loading.spec.js`](../tests/ui/eng_board_progressive_loading.spec.js).
- **All work scope**: union of Component Epics and eligible parents of Department-Team work. [`iter_team_epic_batches`](../backend/services/eng_board.py) preserves the 10,000-row scan bound, filters parent keys in batches, and applies the 1,000-Epic ceiling only to admitted membership; [`discover_team_epics`](../backend/services/eng_board.py) remains the collecting compatibility wrapper. Depends on captured projects, issue types, parent-owned status/retention and strict paging. Tests: [`test_eng_board_service.py`](../tests/test_eng_board_service.py), [`test_eng_board_progressive_loading.py`](../tests/test_eng_board_progressive_loading.py).
- **Strict Board stream**: OAuth-backed `GET /api/eng/board`, [`get_eng_board` / `_frame_stream`](../backend/routes/eng_board_routes.py). Produces protocol-v1 start/index/progress/column/terminal frames. Its route-local candidate policy allocates at most 8 MiB to optional cumulative candidate lines and keeps a 1 KiB terminal reserve inside the unchanged 32 MiB generation limit. [`EngBoardStreamWriter.prepare` / `write`](../backend/services/eng_board_stream.py) provide atomic validation, encoding and sequence admission; [`EngBoardRequestTransport`](../backend/services/eng_board_stream.py) and [`EngBoardChildScheduler`](../backend/services/eng_board_stream.py) retain request-local deadlines and two-child-worker ownership. Tests: [`test_eng_board_routes.py`](../tests/test_eng_board_routes.py), [`test_eng_board_stream.py`](../tests/test_eng_board_stream.py), [`test_eng_board_progressive_loading.py`](../tests/test_eng_board_progressive_loading.py).
- **Board data owner and authority**: [`createEngBoardDataOwner` / `engBoardDataReducer`](../frontend/src/eng/useEngBoardData.js) consume validated frames from [`consumeEngBoardResponse`](../frontend/src/api/engBoardApi.js), preserve generation/scope partitions and cache only completed snapshots. [`useStrictEngBoardPresentation`](../frontend/src/eng/useStrictEngBoardIntegration.js) consumes [`buildStrictEngBoardViewModel`](../frontend/src/eng/engBoardViewModel.js); child authority controls facets and Work items export. Tests: [`test_eng_board_data.js`](../tests/test_eng_board_data.js), [`test_eng_board_stream.js`](../tests/test_eng_board_stream.js), [`test_strict_eng_board_integration.js`](../tests/test_strict_eng_board_integration.js).
- **Board load measurement**: [`createBoardLoadMeasurement`](../frontend/src/eng/loadPerformance.js) is created by the strict owner and consumes optional frame/terminal observations without blocking synchronous reduction. [`load_performance.py`](../backend/services/load_performance.py) validates, persists, and filters Component and All work observations with a null Sprint; these operational records remain outside GA4. Retired or superseded measurements cannot publish late samples. Existing `firstFocusedContentMs` still follows a completed focused column; the joined synthetic campaign measures first visible `.ecard` paint separately in [`eng_board_progressive_loading.spec.js`](../tests/ui/eng_board_progressive_loading.spec.js). Tests: [`test_load_performance.py`](../tests/test_load_performance.py), [`test_load_performance.js`](../tests/test_load_performance.js), [`load_performance.spec.js`](../tests/ui/load_performance.spec.js), [`test_eng_board_data.js`](../tests/test_eng_board_data.js); privacy contract: [analytics](README_ANALYTICS.md). Current evidence is synthetic and test-based; authenticated live first-Epic timing, proxy buffering and the reported production failure's exact bound remain unknown.

## Statistics

Verified on: 2026-09-10.

- **Statistics**: ENG dashboard reporting surface. Entry point: `frontend/src/dashboard.jsx`; API wrappers: `frontend/src/api/statsApi.js`; feature contract: `docs/features/statistics.md`; UI coverage: `tests/ui/codebase_structure_smoke.spec.js`.
- **Statistics source**: cached sprint-scoped Jira Story payload shared by Excluded Capacity, Mono vs Cross, and Project Track. Producer: `fetch_excluded_capacity_stats_source` and `build_excluded_capacity_issue_payload` in `jira_server.py`; route: `backend/routes/stats_routes.py`; contract tests: `tests/test_excluded_capacity_stats_api.py`. Produces normalized Story records with parent-Epic metadata consumed by Project Track.
- **Project Track**: Statistics view that groups Story Points by the parent Epic's Project Track value. Aliases in the UI: Project Track view, Epic mode, Team mode. Aggregation: `frontend/src/stats/projectTrackStats.js`; rendering: `frontend/src/stats/ProjectTrackTotalsBar.jsx`, `frontend/src/stats/ProjectTrackSprintChart.jsx`, `frontend/src/stats/ProjectTrackBreakdownChart.jsx`, and `frontend/src/stats/ProjectTrackPhaseChart.jsx`; tests: `tests/test_project_track_stats.js` and the Project Track case in `tests/ui/codebase_structure_smoke.spec.js`. Depends on the Statistics source and Jira issue-list links.
- **Lead Times**: Statistics view for Epic cohorts and elapsed time. Alias: Cohort Heatmap. Data model: `frontend/src/cohort/cohortUtils.js`; heatmap rendering: `frontend/src/cohort/CohortGrid.jsx`; styles: `frontend/src/styles/stats/cohort.css`; API route: `/api/stats/epic-cohort`; UI coverage: the Statistics and Lead Times cases in `tests/ui/codebase_structure_smoke.spec.js`.
- **Jira issue-list link**: external Jira search navigation for a filtered set of issues. Link analytics contract: `frontend/src/analytics/externalLinks.js`; tracked anchor: `frontend/src/components/TrackedExternalLink.jsx`; taxonomy: `docs/README_ANALYTICS.md`. Consumed by Statistics tables and Lead Times charts.

## ENG shared Sprint selector investigation

Verified on: 2026-09-13 against the current dirty issue #190 source and the local authenticated UI. Mitigation is planned, not implemented.

- **Shared Sprint selector** (UI label: Sprint): `renderSprintControl` in [`dashboard.jsx`](../frontend/src/dashboard.jsx) consumes the ordinary `selectedSprint`/`sprintName` identity, Sprint catalog, and transient `boardStrictScope`. It is shared by Catch Up, Planning, Board, Statistics and Scenario. Current scope-click guards conflate selection with readiness; missing saved Jira authority reproduces ignored Component/All work clicks with a valid catalog. Current ordinary choices remain pointer-selectable; all choices lack keyboard option semantics. Relationships: ordinary Board consumes the Catch Up snapshot; cross-sprint scopes consume the strict owner only. Existing tests in [`eng_group_board_view.spec.js`](../tests/ui/eng_group_board_view.spec.js) encode the old disabled-selection requirement. The [selector mitigation plan](plans/EXEC-eng-board-scope-selector-availability.md) replaces that UI requirement with selectable scopes and explicit waiting/setup states while preserving backend authority; it does not change Sprint catalog implementation.
- **Board scope load authority**: saved Jira projects or Jira source Board from accepted bootstrap, plus capability and accepted Department columns/Components/Teams. Producer: `loadConfig` and `loadGroupsConfig` in [`dashboard.jsx`](../frontend/src/dashboard.jsx); final enforcement: `_resolve_projects` / `_capture_shape` in [`eng_board_routes.py`](../backend/routes/eng_board_routes.py). Department Board columns are not Jira source-Board authority. Live Settings showed absent project/source-Board values, but raw bootstrap capability and storage provenance remain unverified; the plan makes no backend-defect claim.
