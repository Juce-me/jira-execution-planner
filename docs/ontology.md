## Workspace identity and shared catalogs

Verified on: 2026-09-22 against the current source paths and tests named below, except the Sprint catalog entry reviewed on 2026-09-23. Workspace meaning and sharing were confirmed on 2026-09-13; persistent Sprint and per-Sprint Team storage is now implemented locally on this branch.

- **Workspace** (domain aliases: Jira identity, Jira site, Jira domain): the Jira site shared by the entity within one configured application environment. All authenticated users resolved to that environment/site belong to the same catalog scope. The canonical implementation key is `RequestAuthContext.workspace_id`, not a user, OAuth connection, token version, or Department. [`Workspace`](../backend/db/models.py) has unique environment/cloud-ID and environment/site-URL indexes; [`stable_local_workspace_id`](../backend/auth/context.py) uses the environment plus cloud ID, falling back to normalized site URL. [`resolve_db_request_auth_context`](../backend/auth/db_context.py) connects authenticated identity to the persisted workspace. Reuse this resolution rather than inventing a new browser-supplied domain key. Different environments or Jira sites remain isolated. Evidence/tests: [`test_auth_context.py`](../tests/test_auth_context.py), [`test_auth_context_db.py`](../tests/test_auth_context_db.py), [`test_db_migrations.py`](../tests/test_db_migrations.py).
- **Workspace catalogs**: shared derived Jira metadata for one workspace. [`WorkspaceSprintCatalog`](../backend/db/models.py) is keyed by workspace + Jira source Board; [`WorkspaceSprintTeamCatalog`](../backend/db/models.py) is keyed by workspace + Sprint and binds validated membership to an effective-scope digest; [`WorkspaceTeamCatalog`](../backend/db/models.py) is the independent workspace Team-name directory. All authenticated users in the same workspace consume the same saved lists. The refreshing user's identity is authentication/audit context, not catalog ownership or a cache partition. Relationships: consumes effective workspace Jira configuration and authenticated Jira reads; produces Sprint choices, Sprint-scoped Team availability, and Team labels. Tests: [`test_workspace_catalog_cache.py`](../tests/test_workspace_catalog_cache.py), [`test_persistent_catalog_routes.py`](../tests/test_persistent_catalog_routes.py), and [`test_workspace_catalog_postgresql.py`](../tests/test_workspace_catalog_postgresql.py); ownership: [configuration ownership](../backend/security/CONFIGURATION_OWNERSHIP.md).
- **Effective catalog configuration and publication fence**: [`resolve_effective_catalog_config`](../backend/services/workspace_catalog_config.py) consumes saved Board/projects/Team and Sprint fields plus environment-priority base JQL, preserving revision-zero exact-site fallback. [`claim_catalog_refresh`](../backend/services/workspace_catalog_cache.py) and [`publish_catalog`](../backend/services/workspace_catalog_cache.py) share [`acquire_workspace_config_fence`](../backend/services/workspace_dashboard_config.py) with administrator/capacity updates and legacy promotion. Publication re-resolves the configuration and locks the refresh actor's BrowserSession before replacing a complete payload; Team publication also updates discovered names atomically. A changed identity/scope or retired actor cannot publish. [`CatalogRefreshRuntime`](../backend/services/catalog_refresh_runtime.py) owns the two-worker bounded runtime, attempt deadline, lease, and failure classification. Relationships: configuration determines identity; fenced publication produces complete membership and version metadata; completion reads consume only the named attempt and identity.
- **User authorization and preferences**: credentials authorize upstream requests; private preferences remain user-owned. Sharing these catalogs does not change the ownership of issue payload caches, personal connections, saved private views, or Department configuration. Complete refresh results replace the shared catalog under the plan's lease/completeness rules; this is shared metadata, not a per-reader reconstruction of Jira visibility.

## ENG Board cross-sprint loading

Verified on: 2026-09-12 against the local issue #190 follow-up implementation on `bugfix/board-progressive-loading`, from baseline `40bffe7`; the implementation is local and unpublished. Ownership is described as implementation responsibility, not an undocumented team assignment.

- **ENG Board** (UI aliases: Board, Kanban): Epic columns rendered by [`EngBoardView`](../frontend/src/eng/EngBoardView.jsx). Contract: [ENG workflows](features/eng-workflows.md#board-kanban). Ordinary Sprint mode consumes the already-loaded Catch Up snapshot through [`dashboard.jsx`](../frontend/src/dashboard.jsx); only cross-sprint Component/All work uses the strict owner. All ENG work waits for a non-empty Sprint catalog; a saved Sprint label is display-only until that catalog validates it. Once the shared selector is usable, cross-sprint selection is independent of load readiness. Loading still depends on server capability, accepted Department Board configuration, and persisted Jira authority from saved selected projects or a saved Jira source Board. Backend capture resolves and access-checks the saved authority. Tests: [`eng_group_board_view.spec.js`](../tests/ui/eng_group_board_view.spec.js), [`test_eng_board_routes.py`](../tests/test_eng_board_routes.py), [`test_eng_board_service.py`](../tests/test_eng_board_service.py).
- **Sprint catalog**: quarterly Sprint values returned by `GET /api/sprints` in [`settings_routes.py`](../backend/routes/settings_routes.py). In DB/OAuth mode, [`fetch_board_sprints`](../backend/services/sprints.py) reads complete Board pages, accepts Jira's positive reported `maxResults` even when capped below the requested 100, advances by received rows, and rejects incomplete pages before publication. The route reads `workspace_sprint_catalogs`, starts or joins a refresh, and returns server-produced identity, browser-context, validation/version, attempt, deadline, and failure metadata. A validated empty list is authoritative. A matching validated payload remains usable with a nonblocking warning when its refresh fails; a payloadless failure cannot create browser authority. [`createSprintCatalogController`](../frontend/src/dashboardRuntime.js) bounds completion observation to the named attempt and identity, rejects late generations, and cancels on document/auth/config lifecycle changes. Browser cache restoration is display-only until the current server source validates it. Basic file storage and allowed compatibility process caches retain their existing behavior. Tests: [`test_sprint_service.py`](../tests/test_sprint_service.py), [`test_persistent_catalog_routes.py`](../tests/test_persistent_catalog_routes.py), [`test_dashboard_runtime.js`](../tests/test_dashboard_runtime.js), and [`eng_group_board_view.spec.js`](../tests/ui/eng_group_board_view.spec.js).
- **Team name directory and Sprint membership** (verified 2026-09-22): DB/OAuth `GET /api/teams?sprint=…&all=true` in [`eng_routes.py`](../backend/routes/eng_routes.py) reads persisted per-Sprint membership and requires the Sprint to exist in the validated Sprint catalog. Membership identity binds workspace, Sprint, and effective `scopeDigest`; a matching validated empty list removes prior availability. [`buildTeamAvailability`](../frontend/src/settings/teamAvailability.js) combines that authoritative membership with the separate workspace Team-name directory and configured IDs, but only current validated members are addable. Task-derived labels can improve names but cannot grant membership. Failed matching refreshes retain the prior validated membership; identity/scope/auth/modal-generation changes retire it and abort bounded completion work. DB/OAuth disables browser writes of discovered names; legacy modes retain their compatibility behavior. Tests: [`test_sprint_team_service.py`](../tests/test_sprint_team_service.py), [`test_team_availability.js`](../tests/test_team_availability.js), and [`shared_department_groups.spec.js`](../tests/ui/shared_department_groups.spec.js).
- **Component scope**: exact Department `missingInfoComponents` matched on Epic Components, across sprints. [`iter_strict_search_pages`](../backend/services/eng_board.py) validates each Jira page; [`iter_component_epic_batches`](../backend/services/eng_board.py) produces cumulative validated membership and a final marker consumed by [`_frame_stream`](../backend/routes/eng_board_routes.py). Candidate delivery is page-progressive but bounded/coalesced on the wire. Tests: [`test_eng_board_progressive_loading.py`](../tests/test_eng_board_progressive_loading.py), [`eng_board_progressive_loading.spec.js`](../tests/ui/eng_board_progressive_loading.spec.js).
- **All work scope**: union of Component Epics and eligible parents of Department-Team work. [`iter_team_epic_batches`](../backend/services/eng_board.py) preserves the 10,000-row scan bound, filters parent keys in batches, and applies the 1,000-Epic ceiling only to admitted membership; the discovery query stays at its base size because Jira's `nextPageToken` scales with the JQL, so every paged GET is budgeted through [`paged_search_bytes`](../backend/services/eng_board.py) rather than by its first request; [`discover_team_epics`](../backend/services/eng_board.py) remains the collecting compatibility wrapper. Depends on captured projects, issue types, parent-owned status/retention and strict paging. Tests: [`test_eng_board_service.py`](../tests/test_eng_board_service.py), [`test_eng_board_progressive_loading.py`](../tests/test_eng_board_progressive_loading.py).
- **Strict Board stream**: OAuth-backed `GET /api/eng/board`, [`get_eng_board` / `_frame_stream`](../backend/routes/eng_board_routes.py). Produces protocol-v1 start/index/progress/column/terminal frames. Its route-local candidate policy allocates at most 8 MiB to optional cumulative candidate lines and keeps a 1 KiB terminal reserve inside the unchanged 32 MiB generation limit. [`EngBoardStreamWriter.prepare` / `write`](../backend/services/eng_board_stream.py) provide atomic validation, encoding and sequence admission; [`EngBoardRequestTransport`](../backend/services/eng_board_stream.py) and [`EngBoardChildScheduler`](../backend/services/eng_board_stream.py) retain request-local deadlines and two-child-worker ownership. Tests: [`test_eng_board_routes.py`](../tests/test_eng_board_routes.py), [`test_eng_board_stream.py`](../tests/test_eng_board_stream.py), [`test_eng_board_progressive_loading.py`](../tests/test_eng_board_progressive_loading.py).
- **Board data owner and authority**: [`createEngBoardDataOwner` / `engBoardDataReducer`](../frontend/src/eng/useEngBoardData.js) consume validated frames from [`consumeEngBoardResponse`](../frontend/src/api/engBoardApi.js), preserve generation/scope partitions and cache only completed snapshots. [`useStrictEngBoardPresentation`](../frontend/src/eng/useStrictEngBoardIntegration.js) consumes [`buildStrictEngBoardViewModel`](../frontend/src/eng/engBoardViewModel.js); child authority controls facets and Work items export. Tests: [`test_eng_board_data.js`](../tests/test_eng_board_data.js), [`test_eng_board_stream.js`](../tests/test_eng_board_stream.js), [`test_strict_eng_board_integration.js`](../tests/test_strict_eng_board_integration.js).
- **Board load measurement**: [`createBoardLoadMeasurement`](../frontend/src/eng/loadPerformance.js) is created by the strict owner and consumes optional frame/terminal observations without blocking synchronous reduction. [`load_performance.py`](../backend/services/load_performance.py) validates, persists, and filters Component and All work observations with a null Sprint; these operational records remain outside GA4. Retired or superseded measurements cannot publish late samples. Existing `firstFocusedContentMs` still follows a completed focused column; the joined synthetic campaign measures first visible `.ecard` paint separately in [`eng_board_progressive_loading.spec.js`](../tests/ui/eng_board_progressive_loading.spec.js). Tests: [`test_load_performance.py`](../tests/test_load_performance.py), [`test_load_performance.js`](../tests/test_load_performance.js), [`load_performance.spec.js`](../tests/ui/load_performance.spec.js), [`test_eng_board_data.js`](../tests/test_eng_board_data.js); privacy contract: [analytics](README_ANALYTICS.md). Current evidence is synthetic and test-based; authenticated live first-Epic timing, proxy buffering and the reported production failure's exact bound remain unknown.
## ENG Story Readiness

- **Planning hierarchy**: Catch Up's hierarchy with Planning controls, selection, Story Points, and capacity behavior. - **Stories Required**: Catch-Up-only alert for active or future Story requirements. Alias: Needs Stories (legacy future-only name). Classification and target lookup come from `frontend/src/eng/engWorkHierarchy.js`; rendering: `frontend/src/eng/EngAlertsPanel.jsx`; filter projection: `frontend/src/eng/engAlertFilters.js`; local navigation: `frontend/src/eng/alertEpicNavigation.js`. Verified 2026-09-17.
- **Alert filter projection**: shared Catch Up narrowing for every alert category, including server-provided Story alerts and Epic/readiness alerts. Pure entry point: `filterEngAlertCollections` in `frontend/src/eng/engAlertFilters.js`; memoized dashboard integration: `useEngAlertFilters` in `frontend/src/eng/useEngAlertFilters.js`; contracts: `tests/test_eng_alert_search.js`, `tests/ui/eng_alerts_panel_summary.spec.js`, and `tests/ui/eng_missing_story_ghosts.spec.js`. - **Alert Epic candidate**: normalized Epic record returned in `epicsInScope` for Catch Up alert classification. Producer: `fetch_epics_for_empty_alert` in `jira_server.py` and `build_alert_epic_payloads` in `backend/services/alert_epics.py`; consumer: `frontend/src/eng/useEngSprintData.js`. - **Alert-to-item navigation**: local reveal, filter clear, scroll, focus/edit, highlight, and Jira fallback for an alert row. Entry points: `frontend/src/eng/alertStoryNavigation.js`, `frontend/src/eng/EngAlertsPanel.jsx`, and `scrollToTaskItem`/`handleAlertStoryClick` in `frontend/src/dashboard.jsx`; coverage: `tests/test_dashboard_alert_source_guards.js` and `tests/ui/eng_alerts_panel_summary.spec.js`. - **Story requirement**: application-owned representation of one unmet `(Department, selected Sprint, Epic, expected Team)` contribution. Alias: missing-story ghost. - **Story-readiness snapshot**: exhaustive, scope-stamped read model for active/future Sprint coverage. Route: `GET /api/eng/story-readiness` in `backend/routes/eng_routes.py`; pure projection: `project_story_readiness` in `backend/services/story_readiness.py`; effective Department resolver: `load_effective_groups` in `backend/services/shared_group_config.py`; client lifecycle: `frontend/src/eng/useStoryReadiness.js`; contracts: `tests/test_story_readiness.py` and `tests/test_story_readiness_api.js`. It consumes authenticated Jira Epic/Story reads, exact Team labels, canonical sprint metadata, workspace configuration, and project-access state; it produces requirements only after exhaustive pagination and current-scope validation.

## ENG shared Sprint selector and Board load authority

Verified on: 2026-09-22 against `renderSprintControl`, the catalog reducer/controller, readiness resolvers, both data owners, backend capture, and the acceptance matrix.

- **Shared Sprint selector** (UI label: Sprint): `renderSprintControl` in [`dashboard.jsx`](../frontend/src/dashboard.jsx) consumes the ordinary `selectedSprint`/`sprintName` identity, validated Sprint catalog, and transient `boardStrictScope`. It is shared by Catch Up, Planning, Board, Statistics and Scenario. A restored id/label is display-only and cannot authorize ENG Jira work until a matching server identity/browser context validates it; authoritative empty replacement clears available choices while retaining only the saved label for explanation. Native option buttons inside a listbox support pointer and keyboard commitment; the ordinary identity remains persisted while Component/All work is transient. `boardScopeRequested` records selected intent, while `selectedScopeReadiness` decides whether Board shows loading/setup/error or may activate the strict owner. Ordinary/manual refreshes coalesce on one attempt; Retry forces one new attempt only when no ordinary pending attempt exists. Completion is same-attempt, deadline-bounded, generation-guarded, and cancelled on auth/config/document lifetime changes. Relationships: ordinary Board consumes the Catch Up snapshot; Project Track synchronization and cross-sprint authority remain unchanged. Tests: [`test_dashboard_runtime.js`](../tests/test_dashboard_runtime.js) and [`eng_group_board_view.spec.js`](../tests/ui/eng_group_board_view.spec.js). Completed selector plan: [selector availability](plans/DONE-eng-board-scope-selector-availability.md); persistence contract: [persistent catalogs](plans/EXEC-persistent-sprint-team-catalogs.md#browser-authority-and-refresh-completion).
- **Board scope load authority**: `loadConfig` and `loadGroupsConfig` in [`dashboard.jsx`](../frontend/src/dashboard.jsx) produce independently generation-guarded accepted configuration states. A Board-affecting Settings save invalidates the applicable config/group read generations and holds a transaction fence from the first mutation through the designated post-save config acceptance, so pre-save and in-save reads cannot restore stale authority; successful authoritative group-save responses retain their existing acceptance role. `acceptedStrictBoardRevision` combines accepted workspace authority with Department revision/content for strict-owner invalidation. Readiness requires capability, a current accepted read, saved Jira projects or source Board, Department columns, and scope membership; unsaved Settings drafts cannot grant or revoke it. `strictBoardOwnerActive` alone activates `useStrictEngBoardOwner`; requested-but-blocked scopes suppress ordinary fallback. Final enforcement remains `_resolve_projects` / `_capture_shape` in [`eng_board_routes.py`](../backend/routes/eng_board_routes.py). Department Board columns are not Jira source-Board authority. Live saved-authority provenance and positive authenticated cross-sprint loading remain unverified; no backend-defect or widened-authority claim is made.
